# i18n (Vietnamese / Japanese) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add Vietnamese ↔ Japanese language switching to all 69 frontend pages using react-i18next, with a persistent `LanguageSwitcher` button in every layout.

**Architecture:** Install `i18next` + `react-i18next` + `i18next-browser-languagedetector`. Initialize a singleton in `src/lib/i18n.ts` that statically imports 8 translation namespaces per language. A `LanguageSwitcher` component is placed in `DashboardLayout` topbar and the public/auth layouts. All 69 pages replace inline Vietnamese strings with `useTranslation()` hook calls. `src/lib/date.ts` reads `i18n.language` for date-fns locale. A global CSS rule `html[lang="ja"] { font-size: 14px }` compensates for variable text length.

**Tech Stack:** `i18next@23`, `react-i18next@14`, `i18next-browser-languagedetector@8`, date-fns 3.6 (vi/ja locale objects), Zustand 4, Tailwind CSS 3, React 18.3, TypeScript 5.

## Global Constraints

- Default language: `vi`. Fallback: `vi`.
- Second language: `ja`.
- localStorage persistence key: `gym-locale`.
- 8 namespaces: `common`, `auth`, `member`, `trainer`, `staff`, `owner`, `home`, `validation`.
- Key naming: `section.subsection.key` — dot-separated, camelCase leaf names.
- Only UI display text is translated. Mutations and axios calls stay unchanged.
- No backend changes required.
- No test framework exists — verification is manual browser testing.

## Key Naming Convention

```
common.button.save         → "Lưu"             → "保存"
common.status.active       → "Đang hoạt động"  → "アクティブ"
auth.login.title           → "Chào mừng trở lại" → "おかえりなさい"
auth.login.invalidCredentials → "Email hoặc mật khẩu không đúng." → "..."
validation.password.minLength → "Mật khẩu phải có ít nhất 8 ký tự." → "..."
member.dashboard.title     → "Dashboard"       → "ダッシュボード"
staff.dashboard.greeting   → "Xin chào, {{name}}..." → "{{name}}さん、..."
owner.dashboard.totalMembers → "Tổng hội viên" → "総会員数"
```

Rules:
- Namespace = first segment (matches filename).
- Section = page or domain (e.g. `dashboard`, `login`, `register`).
- Leaf key = camelCase, describes meaning not position.
- Dynamic values use `{{variableName}}` i18next syntax.
- Plurals follow i18next `_one`/`_other` suffix when needed.

## CSS Strategy for Variable Text Length

Japanese text is sometimes longer, sometimes shorter than Vietnamese:
- Form labels: often similar (e.g., "メールアドレス" ≈ "Email" in visual weight)
- Button text: Japanese often shorter (e.g., "保存" vs "Lưu")
- Page descriptions, error messages: can be 1.5–2× longer in Japanese

**Primary fix** — reduce Japanese base font size globally in `client/src/index.css`:

```css
html[lang="ja"] {
  font-size: 14px;
  letter-spacing: -0.01em;
}
```

This shrinks all Japanese text ~7% (from 15px Tailwind default → 14px) which prevents most overflow without changing any component.

**Secondary rules** — applied during page migration:
- Buttons with inline text: use `min-w-0`, NOT fixed `w-[Xpx]`.
- Navigation labels: add `whitespace-nowrap`.
- Page headings: use `break-words`, NOT `truncate`.
- Flex rows containing labels: use `flex-wrap`.
- Table `<td>` with status badges: add `min-w-0`.

## Migration Pattern

Applied uniformly to all 69 pages.

### Before (LoginPage.tsx excerpt):
```tsx
function LoginPage() {
  const [error, setError] = useState('')

  const handleSubmit = async () => {
    setError('Email hoặc mật khẩu không đúng.')
  }

  return (
    <div>
      <h1>Chào mừng trở lại</h1>
      <p>Đăng nhập để tiếp tục hành trình của bạn</p>
      <label>Email</label>
      <label>Mật khẩu</label>
      <button>Đăng nhập</button>
    </div>
  )
}
```

### After:
```tsx
import { useTranslation } from 'react-i18next'

function LoginPage() {
  const { t } = useTranslation('auth')
  const [error, setError] = useState('')

  const handleSubmit = async () => {
    setError(t('login.invalidCredentials'))
  }

  return (
    <div>
      <h1>{t('login.title')}</h1>
      <p>{t('login.subtitle')}</p>
      <label>{t('login.email')}</label>
      <label>{t('login.password')}</label>
      <button>{t('login.submit')}</button>
    </div>
  )
}
```

### Multiple namespaces in one page:
```tsx
const { t } = useTranslation('auth')
const { t: tCommon } = useTranslation('common')
const { t: tVal } = useTranslation('validation')
```

### Interpolation:
```tsx
// String in JSON: "greeting": "Xin chào, {{name}}"
t('dashboard.greeting', { name: user.fullName })

// Staff worked time: "workedTime": "Đã làm {{hours}}g {{minutes}}p"
t('dashboard.workedTime', { hours, minutes })
```

```tsx
import { useTranslation } from 'react-i18next'

export function LanguageSwitcher() {
  const { i18n } = useTranslation()
  const isVi = i18n.language === 'vi'

  const toggle = () => {
    const next = isVi ? 'ja' : 'vi'
    i18n.changeLanguage(next)
    document.documentElement.lang = next
    localStorage.setItem('gym-locale', next)
  }

  return (
    <button
      onClick={toggle}
      className="flex items-center gap-1 px-2 py-1 text-sm font-medium rounded-md border border-outline hover:bg-surface-container transition-colors whitespace-nowrap"
      aria-label={isVi ? 'Switch to Japanese' : 'Switch to Vietnamese'}
    >
      <span className={isVi ? 'text-primary font-semibold' : 'text-on-surface-variant'}>
        VI
      </span>
      <span className="text-on-surface-variant">/</span>
      <span className={!isVi ? 'text-primary font-semibold' : 'text-on-surface-variant'}>
        JA
      </span>
    </button>
  )
}
```
